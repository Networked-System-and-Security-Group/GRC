# GSCC ACK/PSN experiments

This directory contains the instrumented Tofino2 data plane and controller,
a parameter matrix, a Python runner, and a C shim that holds the RDMA QPs at
startup until their CNP mapping is installed and read back. The matrix has
seven builds and 238 trial conditions per repetition. It compares exact PSN
matching and signed windows at different slot counts and numbers of QPs.
It uses fixed Write counts for unlimited traffic and 5-second software pacing
for rate sweeps (perftest bandwidth uses the inner three seconds).

The matrix counts positive ACKs, AckReqs, window acceptance and signed offsets
from the **resident probe**. It does not reconstruct the original per-QP
AckReq/ACK pairing. The reported time difference uses the resident probe's
timestamp and is not a reference RTT measurement.

## Preview without hardware

From this directory, using Python 3.10+ with PyYAML and GCC for the tests:

```sh
python3 scripts/matrix.py plan
python3 scripts/matrix.py all --dry-run
python3 -m unittest discover -s tests
```

## Configure and run on hardware

Use a dedicated Tofino2 ASIC with the SDE installed (SDE 9.7.1 was used for the
original experiment) and one Linux traffic host with two ConnectX RoCEv2
interfaces looped through the switch. Use port 1 of two distinct RDMA devices,
two IPv4 addresses and two 100 Gb/s RS-FEC Tofino device ports in the **same
pipe**. The traffic host needs `ib_write_bw` with software pacing and duration
support, GCC, libibverbs headers, `ethtool` and `ip`. The measurement requires
the mlx5 NIC/physical counters used by the runner.

Copy `testbed.example.json` to `testbed.local.json` and fill in:

- `switch_ssh` and `traffic_ssh`: SSH host aliases or `user@host`. Set up SSH
  authentication and verify both hosts in `known_hosts` first.
- `switch_work` and `traffic_work`: dedicated writable absolute directories on
  the respective machines. Use a single orchestrator for this testbed.
- `sde` and `sde_install`: switch SDK and install directories.
  `bfrt_python` is the SDK-compatible Python executable on the switch;
  `bfrt_pythonpath` lists the SDK module directories if needed to import
  `bfrt_grpc.client`.
- `switchd_conf`: an absolute path on the switch to a valid switchd JSON
  configuration for its board, with device 0 and one program and pipeline
  covering the chosen pipe. The runner copies it, points it at the built
  artifacts and sets the program name to `gscc_stat`.
- `endpoints.client` and `endpoints.server`: Linux interface name, RDMA device
  name, IPv4 address and numeric Tofino device port. The runner generates the
  P4 topology header from these fields.

Use an isolated testbed: runs cold-start the managed controller and refuse to
stop an unrelated switch process. The runner records the network configuration
and does not change IPv6 settings.

```sh
python3 scripts/matrix.py build
python3 scripts/preflight.py --qualify
python3 scripts/matrix.py all --keep-going
python3 scripts/audit.py
```

`--qualify` runs a one-QP, 1,000-Write smoke trial for each build, plus a
five-second paced trial for each build with a rate sweep. This checks the
installation and measurement path; it is not an exhaustive hardware
qualification. Preflight checks the saved build, script and hardware
identities again before the full matrix. Run the full command in a terminal
multiplexer for long sweeps. Use `--only-config`, `--only-sweep` and `--limit`
to restrict a run, and `--reps` to keep independent repetitions.

Build records, trial logs, raw counter snapshots and CSV output are generated
locally under `builds/` and `results/`. The testbed file, readiness record,
generated source and run data are excluded from Git. Run the audit against
trial records generated by this version of the scripts.
