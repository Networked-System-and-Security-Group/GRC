# CERNET 多网关与多路径：首轮实验计划

代码从 `dev` 的 `0b56ab0` 起步。保留原版 `cernet_topo`，由实验脚本生成派生配置。本轮在本机编译、跑仿真和分析；原始输出放在 `mix/output/`。服务器恢复后，可通过 Git 同步代码与本目录报告，在 `pengbo29@192.168.5.122:/home/pengbo29/grc` 重跑，原始数据留在运行机器。运行脚本和分析入口单列在根目录实验文件夹。

| 问题及来源 | 对照怎么做 | 看到什么意味着什么 |
| --- | --- | --- |
| 同一瓶颈前，多一个独立控制器会怎样？Shepherd 要求区分测量与控制，并建议小型双网关实验。 | 呼和浩特 DC3 到北京 DC0。复制一个 DC3 网关，保留原接入和骨干拓扑；指定两批相同的长流，第二批延后启动。两批都走原网关 vs. 各走一个网关，ACK 均回原出口。另以现成 DC3/DC4 各一个网关作参照。先关自适应权重，再保留默认权重重复，避免把共享 `k` 的影响解释为控制器彼此独立。 | 观察第二批启动后两个网关的 `refRate`、链路合计速率、队列高度与持续时间、丢包。总流量恢复接近容量可以和队列变高同时出现；若持续振荡，结合 RTT 样本覆盖和饱和程度定位。双源 DC 是近似参照，其源端交换网络不同。 |
| ACK 改走另一个网关时，现有表实际少了多少可用样本？Reviewer B 质疑镜像的开销及扩展性。 | 在同一 DC 配置两个网关，轻载；固定前向路由，比较 ACK 回原网关、部分跨网关及全部跨网关。收集 AckReq 写表、槽位占用、ACK 到达和实际采样事件。以回原网关为对照，不开启镜像，让实验测量原设计的 failure case。 | 只有数据曾成功写表且对应 ACK 抵达另一网关，才是具备匹配条件的跨网关候选；表冲突、序号不匹配、缺 ACK 和未到观测截止分别计数。配置的回程比例不是实际部署的概率。 |
| 一个目的 DC 只维护一个速率时，一条路径堵了，另一条会不会也慢？Reviewer E 也指出路径先天更长可能被误认为拥塞。 | 北京到石家庄用直达和经天津的现成路径，分别钉住两组流。先做空载传播和单路径自校验，再做无背景流量 vs. 在固定时刻向直达路径增加来自 WAN 侧的流量。检查两端接入及备用路径余量。另做轻载下从短路径流切到长路径流，对照同样时刻仍走短路径。 | 若备选路径没积队列，但其流量随共用 `refRate` 下滑，支持控制粒度过粗。若共同接入也拥塞，不能归因于聚合。轻载长路阶段若没有队列但估计延迟抬高，说明不同路径的传播时间混进了拥塞信号。 |

实现步骤：

1. 增加可选的同 DC 附加 DCI，以及按源/目的主机对固定的双向 WAN 路线。未配置时沿用原路由；配置时校验节点归属、物理邻接和正反向路径，并按实际出入口算基准 RTT。
2. 增加诊断日志：可选的逐事件 AckReq/ACK 配对日志、能区分同 DC 两个网关的速率日志。保留原有 GRC 目标速率、采样策略和 CNP 执行机制。
3. 用短跑验证经过的 WAN 链路、流完成情况、ACK 真实归属；随后执行对照并按固定时间窗分别统计。报告记录失败/无效对照和可外推的范围。
